# Границы модулей

- `src-tauri/src/sessions.rs`: контракт сообщений, проверка данных, правила сессий и построение сохранённой ветки истории; без зависимости от assistant-ui.
- `session_store.rs`: SQLite, транзакции и миграция v1/v2/v3 → v4. Сообщение и состояние интеграции сохраняются атомарно.
- `runs.rs`: один активный ход на сессию, отмена по ID, освобождение при любом исходе.
- `conversation.rs`: запись результата до возврата в UI, журнал неудачных попыток, выполнение хода по истории из базы; выбор API или Codex. Codex продолжается только при совпадении модели и сохранённого родительского ответа.
- `providers.rs`: конфигурация провайдеров, Windows Credential Manager, каталог моделей и вызовы Rig.
- `codex.rs`: взаимодействие с Codex App Server, аккаунт, модели, настройки и диалоги. Codex работает отдельно от Rig.
- `plugins.rs`: жизненный цикл встроенных сервисов Cordis.
- `src/sessionHistory.ts`: преобразование сообщений ядра в assistant-ui и обратно; данные интерфейса находятся в пространстве имён `assistant-ui`.
- `src/main.tsx`: представление сессий и runtime чата. История для модели собирается Rust-сервисом из сохранённой ветки.
- `Settings.tsx`, `CodexSettings.tsx`: настройки провайдеров и Codex через статические клиентские вклады.

Формат SQLite принадлежит Minerva. `transcript.rs` описывает части и связи вызовов/результатов; `rig_history.rs` и `codex_history.rs` переводят данные движков и передают снимки через узкий callback. Сериализованные сообщения Rig сохраняются только в `extensions.replay`, отдельно от общей проекции. Подробности: [docs/structured-history.md](docs/structured-history.md). Вложения и потоковый транспорт остаются следующими этапами.
