# Память и улучшение харнеса

Локальный runtime предоставляет семь необязательных плагинов. Откройте «Плагины», включите нужный плагин и нажмите «Открыть». Выбор сохраняется в `minerva.conf.json`; общий переключатель приостанавливает инструменты, контекстные дополнения и выполняемые эксперименты, сохраняя данные и индивидуальный выбор.

| ID | Что делает | Зависимости |
| --- | --- | --- |
| `session-query` | Поиск видимого текста сессий, точное чтение и ссылки на оригинальные события | sessions, workspaces |
| `skills` | Локальные и управляемые навыки, версии, публикация и откат | context |
| `memory` | Факты, предпочтения, уроки, поиск, подтверждение конфликтов и аудит | context |
| `experience` | Неизменяемые bundles и опыт завершённых экспериментов | — |
| `experiments` | Ограниченные прогоны моделей, артефакты, расход и отмена | skills |
| `improvement` | Propose–Probe–Compose, выбор результата и рефлексия | experiments, experience |
| `skill-curation` | Контрольные задачи, два ревью, публикация проверенного навыка | skills, experiments, session-query |

Новые возможности выключены по умолчанию. Исключение — `skills`: при отсутствии сохранённого выбора он включён для совместимости с прежним `load_skill`; явное отключение сохраняется. Требуемые зависимости видны в списке. Hosted-профиль эти локальные сервисы не включает. Файлы стороннего memory MCP по-прежнему подключаются через существующий менеджер MCP; автоматического объединения его хранилища с памятью Minerva нет.

## Память и история

В панели выберите чат. По умолчанию используется область его рабочего пространства; «Личная область» доступна для общих фактов текущего пользователя. Рабочее пространство и пользователь определяются хостом. Переданный в JSON путь не даёт доступа к другому пространству.

Запись памяти можно добавить, найти, прочитать, изменить с проверкой версии и отозвать. Предположения имеют статус pending и не попадают в контекст до подтверждения. Конфликтующие записи с одинаковым `cue` требуют решения; подтверждение нового значения переводит прежнее активное значение в superseded. Это не универсальное семантическое определение противоречий.

На каждом обычном шаге модель получает ограниченный набор активных записей: тематический поиск и основные факты. Пустая память не добавляет секцию. Текст помечается как справочные данные и не меняет разрешения инструментов. Полные тексты и источники доступны через инструменты `memory_search`, `memory_read`; явные записи и отзыв — через `memory_remember`, `memory_forget`. Самостоятельное неограниченное переписывание памяти не включено.

История индексирует видимый user/assistant-текст, включая сообщения старых snapshots; reasoning и бинарные вложения не индексируются. Результат содержит ограниченный фрагмент и точный SourceRef с digest. При чтении источник проверяется заново. Новые forks сохраняют provenance и используют ссылки на оригинал; старые ветки без таких данных не получают выдуманного происхождения. Внутренние сессии пробных прогонов исключены из списка чатов и индекса.

## Навыки

Каталог объединяет разрешённые файловые providers и управляемые публикации. Проектные `.agents/skills` и `.claude/skills` остаются доступными после включения `skills`; тело перечитывается при загрузке, путь ограничивается выданным хостом корнем. Учитываются `disable-model-invocation` и `user-invocable`.

Существующий выбор навыков остаётся в `selected_skills`. Обычный чат загружает актуальную версию по имени; эксперимент фиксирует текст и версии в неизменяемом снимке контекста. Публикация и откат проверяют базовую ревизию. Для curation изменения указателя и audit записываются одной транзакцией; повтор с тем же requestId возвращает прежний результат.

## Эксперименты и Propose–Probe–Compose

Укажите задачу, native API-модель и лимит вызовов. Плагин `experiments` выполняет один baseline-прогон; `improvement` проводит полный цикл:

1. Baseline.
2. Общее и предметное предложения.
3. Прогоны обоих вариантов.
4. Композиция изменений и окончательный прогон.
5. Выбор готового результата при `k > 1` и рефлексия.

Доступны последовательная и параллельная стратегии, `k = 1..5`. Параллельная стратегия исследует независимые варианты; текущий исполнитель обрабатывает стадии одного job последовательно. Общий лимит одновременно исполняющихся model calls — два.

При `k=1` требуется 8 вызовов: 4 исполнения, 3 редакторских этапа и рефлексия. При `k>1` — `7k + 2`, включая выбор. Это дополнительные вычисления, а не бесплатное повышение качества. Счётчик включает редактора и выбор; неизвестный фактический usage остаётся unknown с сохранением оценочного резерва.

Каждый child получает зафиксированный контекст и пустой список инструментов. Загрузка текущих AGENTS, памяти и навыков в такой сессии отключена. Изменение компонента — полный UTF-8 replacement фиксированного файла, не unified diff. Перед probe хост материализует bundle и вычисляет digest. Поддержаны task-local `systemPrompt`, `toolGuidance`, `memory`, `skills`.

Скрипты, изменения исполняемого middleware, произвольные tool-using subagents и внешние model engines в этом локальном адаптере отклоняются. Существующий Linux Docker/runsc runner требует отдельной конфигурации и не подменяется shell с рабочим каталогом. Эти возможности исходного плана не объявляются реализованными данным адаптером. На машине проверки Docker Linux daemon был недоступен.

Задание принадлежит runtime: закрытие вкладки не отменяет его. Отмена прекращает admission, останавливает children и ожидает их завершения. Shutdown освобождает lease даже при сохранённых ссылках на runtime. Возобновление improvement проверяет исходную спецификацию, модель, библиотеку и журнал. Стадия, отправленная без подтверждённого ответа, не повторяется автоматически: возвращается `UNCERTAIN_STAGE`.

## Опыт и развитие навыков

Reflection может не сохранить ничего. Для записи опыта нужны завершённый эксперимент, артефакты с проверенными digest и поддерживающая их трасса. Без объективной проверки результат остаётся provisional. Такие записи предлагаются будущему редактору как гипотезы с условиями и ограничениями; они не становятся постоянными инструкциями. Каждая задача начинает с общего baseline, библиотека фиксируется на весь её цикл.

Для проверки изменения навыка сначала настройте gate: executor, два reviewer-профиля с разными provider ID, triggering case и как минимум один holdout. В каждом кейсе заданы вход, обязательные и запрещённые подстроки. Эти проверки ограничены явно заданными утверждениями; они не доказывают корректность произвольной программы. Разные provider ID также не доказывают независимость моделей.

Затем создайте предложение с базовой ревизией, новым текстом, объяснением и источником из истории. Gate сохраняется вместе с предложением: последующее изменение настроек не ослабляет его. Проверка сравнивает baseline и candidate на каждом кейсе, требует исправления triggering case без новых регрессий и два reviewer verdict. Только Ready можно опубликовать. Ошибочный ответ reviewer, дрейф версии или недоступный источник закрывают gate. Предусмотрены отмена, восстановление неоднозначной публикации и откат.

## Хранение и контракты

Данные расположены в `<dataDir>/learning/`: отдельные SQLite stores, derived history index и content-addressed артефакты. Ими владеет один runtime. Исходная история остаётся в sessions store. Перед обновлением sessions v5→v6 создаётся `.pre-v6-*.sqlite3`; старые v1–v4 сохраняют прежнюю `.pre-v5-*` копию. Более новый формат отклоняется. Purge удаляет логическое содержимое и индексы, но не обещает физического стирания из файлов SQLite или резервных копий.

Оба транспорта используют существующий контракт `plugins.call`:

```json
{"id":"memory","method":"search","params":{"sessionId":"chat-id","payload":{"query":"правило проверки"}}}
```

Необязательный `scope` имеет вид `{"kind":"user"}`, `{"kind":"workspace","workspaceId":"..."}` или `{"kind":"session","sessionId":"..."}`. Его полномочия проверяет host. Поля actor, пути БД и разрешения не принимаются от модели. Управляющие операции доступны через UI/API; модель получает только зарегистрированные инструменты. Несовместимые версии и ошибки не превращаются в успешный текст ответа.
