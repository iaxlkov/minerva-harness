# Аудит ядра — 2026-11-06

Продолжение от 2026-11-07: [архитектура web-платформы](superpowers/specs/2026-11-07-web-platform-design.md) и [фактический прогресс реализации](validation/web-platform-progress.md). Приведённые ниже проверки относятся к историческому этапу, а не подтверждают готовность многопользовательского сервера.

База сравнения: Minerva `75dfe01`, Rig 0.46.0 из Cargo.lock и локального registry; актуальные документы DeepSeek Harness. Это аудит исходников, не доказательство отсутствия всех багов и не обещание полного функционального паритета.

## Источники и решение

- [DSH architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md): разделение модели, инструментов, сессии и исполнения; жизненный цикл хода.
- [DSH sessions](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session.md): журнал фактов отдельно от проекции истории и неудачных попыток.
- [DSH LLM](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/llm-streaming.md): нейтральные сообщения, состояние адаптера и потоковый протокол.
- [Rig agents](https://www.rig.rs/docs/concepts/agent), [durable runs](https://www.rig.rs/docs/concepts/runs): готовый цикл, история и сериализуемый AgentRun. Локальный `rig-agent-0.46.0/src/agent/completion.rs` подтверждает: chat изменяет переданный Vec после успеха, сохранением владеет вызывающий код.

Оставляем SQLite и Cordis. Не копируем всю плагинную систему DSH и не пишем собственный цикл инструментов поверх уже имеющегося Rig. Формат сессии принадлежит Minerva; Rig и Codex адаптируются на границе. Полная сериализация AgentRun полезна позже для долгих операций и approvals, но не заменяет общий контракт истории двух движков.

## Исправления текущего этапа

Строки ниже реализованы в коде; проверка перечислена в заключительном разделе. Они не означают завершение следующих этапов паритета.

| P2 | Устаревшие chat/codex_chat IPC обходят сохранение и правила сессии | Удалить обходные публичные команды; оставить адаптеры внутренними |

## Малые контракты до рефакторинга

- `sessions`: типы сессии, валидация, неизменяемая ветка. Не знает Tauri, Rig, Codex или React.
- `session_store`: SQLite и миграции, транзакционные инварианты, запись результата и состояния хода.
- `runs`: владение активным выполнением и отменой. Контракт acquire/cancel; освобождение при любом исходе.
- `conversation`: оркестрация сохранённого запроса → адаптер → сохранённый результат. Только здесь выбирается движок.
- `codex`: процесс/RPC и интерпретация его состояния; `providers`: конфигурация и Rig-адаптация.
- `sessionHistory`: преобразование DTO в assistant-ui; UI не владеет записью результата модели.

## Последующие этапы функционального паритета (не выдавать за готовые)

1. Tool-call/tool-result и provider replay state реализованы вторым этапом ниже. Вложения и usage ещё предстоят.
2. Потоковый транспорт с runId/sequence, частичные ответы и восстановление после reconnect. Отдельно live-дельты и durable итог/попытка.
3. Подключение оболочки к Rig ToolSet через policy/approval и рабочую директорию. Сейчас оболочка — ручная команда UI, не инструмент агента. Windows child.kill завершает только оболочку: до агентного применения нужны Job Objects и тест дочерних процессов.
4. Контекстный бюджет, compaction и сохранение точного system prompt/настроек/версии адаптера для воспроизводимости. Нельзя молча обрезать историю.
5. Состояния провайдеров и единый каталог capabilities; запрашивать только поддерживаемые effort/модальности. Без выдуманных универсальных настроек.
6. Пагинация диалогов/сообщений и ленивое восстановление для больших баз; резервное копирование. Одновременный доступ двух новых экземпляров теперь запрещён файловой блокировкой; полноценный multi-process режим не реализован. Старый бинарник блокировку не соблюдает: его нужно закрыть до обновления.
7. Восстановление Codex через полноценный адаптер событий. Текущий перенос старой текстовой истории в новый Codex thread — текстовый transcript, не точное восстановление ролей, tool state и approvals.
8. Повторное использование App Server и единый транспорт status/login/models/chat. Фоновый login теперь отменяется при уничтожении сервиса; остальные операции пока запускают отдельные процессы.

## Сравнение после первого этапа (до структурированной истории)

| Область | DeepSeek Harness | Minerva сейчас |
|---|---|---|
| История | Append-only события и производная проекция | Неизменяемые сообщения с parentId, отдельный журнал запусков SQLite; это ещё не полноценный event sourcing |
| Исполнение | Turn/step, очередь ввода, несколько запросов и инструменты | Один ход на сессию, отмена и запись исхода; API-цикл выполняет Rig, без подключённых инструментов |
| Адаптеры | Общие сообщения и потоковые события | Три API-протокола Rig и отдельный Codex; общий текстовый контракт |
| Сохранение | Публикация durable событий независимо от UI | Rust атомарно пишет ответ + integration state + completed; UI только отображает |
| Возобновление | Производная история, ветвление, состояния адаптеров | Текстовая ветка; Codex resume только от подтверждённого ответа; после сбоя новый thread |
| Расширение | Подменяемые службы Cordis и клиентские вклады | Встроенные Cordis-сервисы, статические настройки React |
| Контекст | Системные события, budgets, compaction | Записаны модель, настройки, ID входа и API-preamble; полный snapshot capabilities и compaction отсутствуют |

Найденные ограничения не скрываются: shell timeout ещё не гарантирует завершение дерева дочерних процессов; Rig output() не является полной историей инструментов; при переносе в новый Codex thread точная семантика старых ролей не сохраняется. Эти три пункта требуют следующей итерации до использования как полноценного coding-agent.

Регрессии: изоляция веток/сессий; отсутствующий родитель; подмена сообщения; сбой транзакции; одновременные запуски; отмена; неудачный ход без assistant; миграция v1/v2; сохранение ответа до UI; ранние RPC-уведомления; ключ не уходит на другой endpoint. ## Результат проверки

- `cargo test -j 2`: 18 passed, 3 ignored. Два ignored-теста требуют реального Codex; третий — диагностика заранее подготовленной копии БД.
- `migrate_backup_copy -- --ignored`: отдельно пройден на копии v1 с двумя сессиями и четырьмя сообщениями. Независимая SQLite-проверка подтвердила v3, прежние ID, родителей, роли, даты, текст и `quick_check=ok`. Рабочая БД не изменялась.
- `cargo clippy --tests -- -D warnings`: успешно.
- `npm test`: 4 теста — контракт IPC, ошибки вне model history, отмена, восстановление ответа без UI-метаданных.
- `npm run build`: успешно; остаётся предупреждение Vite о размере bundle (около 946 kB, gzip 286 kB), оптимизация загрузки не входила в исправления состояния сессии.
- Настоящий React/assistant-ui в браузере с тестовым IPC: отказ → следующий успешный ход, отмена, новая сессия → возврат и восстановление истории. Это не end-to-end проверка Tauri с рабочей SQLite.
- Три Rig HTTP wire проверены локально: Chat Completions, Responses и Anthropic. Реальные endpoint, квоты, login и платные модели не тестировались.
- Схемы уведомлений сверены с `codex.exe app-server generate-json-schema` установленного клиента. После отключения/тайм-аута Codex сохранённая привязка намеренно не переиспользуется: отсутствие удалённых побочных эффектов такой отменой не гарантируется.

Следующий приоритет — пункты 1–3: они блокируют расширение из текстового чата в агент с инструментами. Чистота текущего текстового ядра подтверждена перечисленными проверками, абсолютное отсутствие дефектов ими не доказывается.

## Второй этап — структурированная история, 2026-11-06

Реализованы общий формат вызовов/результатов, сохранение полных сообщений Rig, адаптер items Codex, промежуточные снимки выполнения и восстановление карточек в чате. Ответ с инструментами больше не сводится к `output()`. База v4 сохраняет данные v1–v3; незавершённые снимки остаются в ветке с отдельным статусом. Детальные контракты и ограничения: [structured-history.md](structured-history.md).

Пункты первого аудита про потерю инструментов через `output()` устранены. Ограничения запуска дерева процессов shell и точного переноса истории в новый Codex thread остаются. Следующий этап — потоковый транспорт с восстановлением после reconnect, затем безопасное подключение инструментов плагинов к Rig.

Проверки второго этапа: 23 Rust-теста прошли, 3 ignored; отдельный `migrate_backup_copy` прошёл на копии v3, сравнение всех таблиц подтвердило неизменность 2 сессий, 4 сообщений и 1 integration state, `quick_check=ok`, версия 4. Frontend: 8 тестов, TypeScript/Vite build. Строгий Clippy: без предупреждений. Браузерная проверка выполнена с тестовым IPC; реальный Tauri с рабочей БД не перезапускался.
