# Конфигурация Minerva

`minerva.conf.json` находится в `RuntimeConfig.config_dir`. В desktop это
`%APPDATA%\ru.oestudio.rig.prototype\minerva.conf.json`; сервер использует
каталог `--config-dir`. Пример: [minerva.conf.example.json](../assets/minerva.conf.example.json).

Файл создаётся автоматически при первом запуске или установке пакета. Если его
ещё нет, импортируются лимиты из `shell.json` и выбор плагинов из
`plugin-lock.json`. Старые файлы не удаляются и больше не переопределяют новый.
История, аккаунты и секреты при этом не переносятся и не сбрасываются.

| Поле | Значение и ограничения |
|---|---|
| `version` | Обязательное целое `1` |
| `optionalPluginsEnabled` | По умолчанию `true`; общий переключатель несистемных плагинов |
| `plugins.<id>.enabled` | Индивидуальный выбор установленного плагина; по умолчанию отключён. `example` по умолчанию включён |
| `services.shell.timeoutMs` | По умолчанию `120000`, от `100` до `3600000` |
| `services.shell.maxOutputBytes` | По умолчанию `64000`, от `256` до `1000000` |
| `services.agent-loop.shutdownTimeoutMs` | По умолчанию `5000`, от `100` до `60000`; общий срок ожидания завершения задач перед abort/join |

Отсутствующие необязательные секции используют defaults. Неизвестные поля,
неподдерживаемая версия и недопустимые значения дают ошибку с именем файла.
Проверка выполняется до открытия runtime-хранилищ и запуска внешних плагинов.

Изменения через UI применяются сразу и атомарно сохраняются в этот же файл.
Ручное редактирование требует перезапуска. При параллельном сохранении разных
полей операции перечитывают файл под общим writer lock; несвязанные секции не
теряются. Синтаксическая ошибка не заменяет конфиг defaults.

Системные плагины обязательны; `enabled: false` для них запрещён. Профиль
hosted сохраняет свои ограничения независимо от настроек файла. Конфиг
определяет параметры уже собранных сервисов, а не загружает произвольные
библиотеки. Порядок JSON-полей не задаёт порядок активации.

`plugin-lock.json` хранит package digests для проверки целостности. Старые
enabled-поля в нём могут остаться после миграции, но источником выбора служит
`minerva.conf.json`. Установка нового пакета оставляет его выключенным до
явного включения. Запись отсутствующего пакета сама его не устанавливает;
менеджер показывает ошибку отсутствия пакета.

Provider credentials остаются в credential store; MCP-серверы — в `mcp.json`;
настройки сессий и история — в существующих SQLite-хранилищах. Внешний Codex
сохраняет собственные настройки через свой settings API. Произвольный `config`
для внешних пакетов пока не является частью SDK initialize.
