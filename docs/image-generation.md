# Генерация изображений

Механизм принадлежит харнесу (`plugins/mh-plugin-manager/src/plugins/images.rs`). Плагины расширяют его генераторами. Он не зависит от модели чата, URL сервера, ключей или реализации ComfyUI/Codex.

Модель с поддержкой инструментов получает общие `generate_image({prompt})` и `image_status({generatorId,jobId})`. `generate_image` запускает задание один раз, ожидает его завершения и возвращает ссылку на сохранённое вложение сессии. `image_status` также остаётся для ранее начатых заданий. Перед отправкой харнес проверяет включённые генераторы. Если доступен один, использует его; если несколько, показывает стандартный вопрос пользователю. До ответа генерация не запускается. Если выбранный генератор отказывает, харнес возвращает ошибку, не переключаясь на другой и не повторяя запрос. При отсутствии доступных генераторов возвращается явная ошибка. Когда все плагины генерации отключены, общие инструменты исчезают из следующего каталога.

Выбор запоминается отдельно для каждой сессии в `context.sqlite3` и сохраняется после перезапуска. Пока выбранный генератор доступен, повторного вопроса нет, даже если появился второй генератор. Если выбранный стал недоступен, харнес просит выбрать замену, в том числе при единственной доступной альтернативе. Отсутствие доступных генераторов не стирает выбор. Параллельные вызовы одной сессии используют один вопрос.

Применяются обычные разрешения инструментов: создание изображения имеет побочный эффект, проверка статуса — нет. Выбор генератора и разрешение запуска — разные действия. Внешние LLM и локальные движки используют один механизм.

## Контракт плагина

В manifest: `"capabilities": ["tools", "image-generation"]`. Плагин реализует:

- `images.available({})` → `{"available":true,"name":"Читаемое имя генератора"}`. Ответ должен укладываться в 10 секунд (host deadline — 12 секунд), без генерации и списания лимитов. При ошибке сети/авторизации возвращать `available:false` и безопасную диагностическую строку `reason`. Если все проверки неуспешны, харнес показывает причины по генераторам.
- Обычный контракт `tools.start/poll/cancel/release`, описанный в [backend-plugins.md](backend-plugins.md), с backend-инструментами `generate_image({prompt})` и `image_status({jobId})`.
- `generate_image` сразу возвращает `{"jobId":"opaque-id","status":"running"}`. Долгая работа выполняется фоном, JSON-RPC reader остаётся отзывчивым.
- `image_status` возвращает `running`, `failed` с безопасной ошибкой либо `completed` с абсолютным локальным `path`, `mimeType`, `bytes`. Байты изображения не передаются в poll-кадрах.

Харнес сам опрашивает выбранный плагин, проверяет путь внутри его каталога данных, тип и размер изображения, сохраняет результат во вложениях текущей сессии и возвращает `attachment` вместе с `generatorId`. Чат отображает ссылку как `ImageMessagePart` и загружает содержимое через `attachments.get`, в том числе после перезагрузки. Отмена не запускает повторно работу, уже отправленную генератору. Его приватные генераторные инструменты не попадают в каталог модели под отдельными именами, поэтому выбор нельзя обойти другим названием инструмента. Обычные инструменты плагина продолжают работать.

## Реализации

- `C:\dev\minerva-codex-plugin`: ChatGPT через установленный Codex и его учётную запись подписки. Генерация расходует лимиты Codex. API-key auth не используется.
- `C:\dev\minerva-home-plugin`: домашний Qwen Image через защищённый `llm.mi-nerva.ru`; тот же плагин публикует языковые модели. В настройках нужен только токен, который сохраняется в Windows Credential Manager.

Minerva Home координирует свои текстовые запросы и Qwen на общей GPU: дожидается конца текстовых запросов, выгружает модели Ollama (`keep_alive:0`), выполняет генерацию и освобождает память ComfyUI при пустой очереди. Текстовые запросы через этот плагин ждут завершения картинки. Сторонние клиенты Ollama/ComfyUI и старый MCP эту координацию не используют.

Задания не повторяются после неизвестного результата отправки. Перезапуск плагина прерывает его наблюдение за работой; ComfyUI может продолжать серверное задание. Созданные файлы сохраняются в dataDir плагина.

Проверки: `cargo test -p minerva-runtime --test image_generators` использует настоящие процессы плагинов и проверяет доступность, вопрос до отправки, направление результата, отсутствие fallback и отключение. Локальная генерация через Minerva Home дополнительно проверяется явным `tests/live_smoke.py --live --token-file ... --data-dir ... --images`.
