# Сервисы выполнения и minerva.conf.json

Статус: согласовано пользователем; имя файла — `minerva.conf.json`.

## Объём

Перевести существующие sessions/run lifecycle под управление системных плагинов
Cordis и добавить конфигурацию композиции. Новые MCP resources, jobs,
subagents/teams/plan из сравнительного отчёта — отдельные функциональные задачи.

## Владение сервисами

- `sessions`: публикует существующий `SessionService`; владеет открытием SQLite,
  восстановлением незавершённых запусков и закрытием хранилища.
- `agent-loop`: зависит от sessions, manager/providers и harness services;
  владеет `Runs`, admission/shutdown gate и JoinHandles supervisor. При disposal
  запрещает новые запуски, отменяет текущие, ждёт завершения, затем abort/join
  оставшихся задач. Закрытие sessions происходит после этого.
- `Runtime` — композиционный фасад. Существующие start/get/cancel API делегируют
  сервису; transport handlers не начинают владеть задачами или SQLite.
- Не создавать цикл `Runtime -> service -> Runtime`: supervisor получает
  нужные сервисы явно. Существующий `conversation::run_inner` сохраняется.
- Публикация без фактического переноса tasks/shutdown не считается завершением.
- Оба ID зарезервированы в SDK и отображаются обязательными в менеджере.

## Формат конфигурации

По умолчанию `<RuntimeConfig.config_dir>/minerva.conf.json`. Для Tauri это каталог
`%APPDATA%/ru.oestudio.rig.prototype`. Tenant/workspace и каталоги по-прежнему
выбирает host: редактирование файла не меняет границы workspace/hosted profile.

JSON использует уже установленный serde_json, поддерживает version/schema и
даёт одинаковое поведение Tauri/server. YAML ближе к названию файла DSH, но
потребует отдельного parser; JS expressions/DSH patch DSL здесь не нужны.

Предлагаемая схема первой версии:

```json
{
  "version": 1,
  "optionalPluginsEnabled": true,
  "plugins": {
    "example": { "enabled": false },
    "codex": { "enabled": true }
  },
  "services": {
    "shell": { "timeoutMs": 120000, "maxOutputBytes": 64000 },
    "agent-loop": { "shutdownTimeoutMs": 5000 }
  }
}
```

Все секции, кроме версии, имеют документированные defaults. `plugins` задаёт
индивидуальный выбор optional plugins; master switch приостанавливает их,
сохраняя этот выбор. Системные сервисы нельзя отключить этим списком.
Hosted profile не получает локальные capabilities через конфиг.

`services` принимает реальные реализованные параметры: лимиты shell и ожидание
shutdown agent-loop. Неизвестные поля, неподдерживаемая версия, некорректные
значения и попытка отключить системный сервис дают понятную ошибку с путём
файла до открытия БД/старта процессов. Каталог доступных сервисов определён
сборкой; файл не загружает произвольный Rust-код.

Настройки внешнего Codex продолжают принадлежать внешнему пакету и его settings
API. Эта версия не обещает передачу произвольного `config` внешнему процессу:
существующий SDK initialize такого контракта не имеет. API-ключи, OAuth-токены,
история, MCP server config и session workspace settings сохраняются в своих
существующих хранилищах.

## Сохранение и совместимость

- UI-переключатели плагинов и shell settings пишут в `minerva.conf.json` атомарно;
  host проверяет новое значение до изменения состояния.
- `plugin-lock.json` остаётся хранилищем package digests. Старые enabled поля
  служат источником одноразовой миграции при отсутствии `minerva.conf.json`.
- При первом запуске без нового файла импортируются текущие optional/example/
  installed enabled flags и shell settings. Старые файлы сохраняются; при
  существующем новом файле они больше не переопределяют его значения.
- Установка пакета и состояние включения используют общий writer lock;
  загрузка/сохранение не теряет чужие записи и не заменяет неизвестные секреты.
- Файл читается при запуске. Ручное изменение применяется после перезапуска;
  hot reload не входит в первую версию. UI применяет свои операции сразу.
- Существующий конфиг не перезаписывается defaults при ошибке чтения.

## Проверки

1. Конфиг: defaults, round trip, неверная версия/поля/лимиты, запрет отключения
   system, hosted restrictions, миграция сохранённого выбора, повторный запуск
   без повторного импорта, сохранение digest и иных записей.
2. Lifecycle: реальная доступность sessions/agent-loop через Cordis; отказ
   последующего плагина освобождает SQLite и ранее запущенные fibers.
3. Supervisor: идемпотентный start, один run на session, cancel, отказ старта
   при shutdown, bounded drain/abort, запись terminal статуса до закрытия SQLite.
4. API и process regression: текущие runtime/API тесты и внешний Codex smoke;
   обновление reserved IDs, fixtures и контрактов по фактическому diff.
5. Desktop: запуск Tauri, список системных плагинов, сохранение и восстановление
   переключателя, MCP discovery и один подтверждённый инструмент из чата.

Фронтенд-редизайн, перенос всей конфигурации в один файл, динамическая загрузка
библиотек, YAML patches и горячая перекомпозиция в эту задачу не входят.
